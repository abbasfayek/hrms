3. CURRENCY MODEL (enforced by currencyGovernance.js — Phase 4, unchanged)
--------------------------------------------------------------------------------
  * Base Currency: settings.baseCurrency (default USD)
  * Exchange Rate: manual entry, append-only, locked when referenced by committed record
  * Transaction-level Snapshot: every committed financial record carries
    currency, exchangeRate, exchangeRateDate, baseCurrency, baseAmount, governance
  * Conversion: baseAmount = amount × exchangeRate (multiplicative convention)
  * Precision: amounts 2 decimals Half-Up, rates 6 decimals
  * Mixing Guard: sumSameCurrency() groups by currency; assertSameCurrency() fails on mix
  * Base Aggregation: sumInBase() uses EACH entry's own snapshot (never current rate)
  * Revaluation: NONE — historical baseAmount never rewritten

--------------------------------------------------------------------------------
4. SOURCE OF TRUTH — Report Data Pipeline
--------------------------------------------------------------------------------
  Report Layer          Source of Truth                          Recalculation?
  ---------------------------------------------------------------
  Audit Report          storage.payrolls (stored batches)        NO
  Comparison Report     storage.payrolls (stored batches)        NO
  Payroll Report        storage.payrolls (stored batches)        NO
  GOSI Report           current employee data (known GAP)        YES (recalculates)
  EOSB Report           storage.eosb (stored settlements)        NO
  Overtime Report       storage.overtime (stored records)        NO
  Leaves Report         storage.leaves + calculateLeaveBalance   NO (balance is computed but from stored leaves)

  Key Principle: Financial reports read from STORED committed records with their
  sealed snapshots. Only GOSI currently recalculates from live employee data
  (documented as GAP — see §9).

--------------------------------------------------------------------------------
5. CURRENCY MIXING — Enforcement Verified
--------------------------------------------------------------------------------
  * sumSameCurrency() returns per-currency segments, never merged number
  * assertSameCurrency() returns { ok: false, error: 'currency_mix:USD+IQD', segments: [...] }
  * sumInBase() converts each entry via its OWN snapshot, then sums baseAmount
  * summarizeCurrencySegments() produces "1,000.00 USD + 1,500,000.00 IQD" (not 1,501,000)
  * Reports display: USD Total | IQD Total | Base Total (from baseAmount snapshots)
  * No report produces a single mixed-currency total

--------------------------------------------------------------------------------
6. HISTORICAL EXCHANGE RATE — Immutable
--------------------------------------------------------------------------------
  * Record created at Rate 1480 → baseAmount = amount × 1480 sealed
  * Current rate changed to 1500 → historical record keeps Rate 1480, baseAmount unchanged
  * stampEosbRecord/stampPayrollRecord with force=false preserves existing snapshot
  * convertWithSnapshot() uses provided snapshot, never consults current settings
  * Test HER-1 through HER-8 all PASS

9. KNOWN GAPS (not fixed in Phase 8 — requires Business Decision)
--------------------------------------------------------------------------------
  GOSI Report: Currently recalculates from CURRENT employee data (basicSalary + housingAllowance),
  not from Payroll Snapshot. This means if employee salary changes after payroll is paid,
  GOSI report shows different numbers than the paid payroll.
  Impact: GOSI totals may not match Payroll totals historically.
  Status: Documented, test GOSI-1 PASS (explicitly asserts the gap).
  Recommendation: Phase 9+ to add GOSI snapshot to payroll batch or compute GOSI at payroll commit time.

11. VALIDATION — Edge Cases
--------------------------------------------------------------------------------

  * invalid currency (XYZ) → exchangeRateStatus = 'missing', baseAmount = null
  * missing exchange rate → exchangeRateStatus = 'missing', baseAmount = null
  * baseAmount mismatch detection via convertWithSnapshot
