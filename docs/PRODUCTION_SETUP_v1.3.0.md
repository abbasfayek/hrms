# HRMS / BinoSoft v1.3.0 — Production Setup Checklist (Operator)

**Scope:** first manual production installation of v1.3.0 (Release Candidate).
**Release anchor:** Version `v1.3.0` **Release Candidate**. Current candidate HEAD: `ad72e4d80faee946d53126a74a97c1657b905bcf`. Git tag `v1.3.0`: **PENDING**. Final release SHA: **PENDING** (will be recorded after the release commit/tag).
**Companion file:** `docs/TEMPLATE_users.json.example` (schema template — outside `data/`, not a live file).

> **HARD RULE — DO NOT manually edit `users.json`, `companies.json`, `payrolls.json`, audit files (`audit.json`, `audit_trail.json`, `deleted_records.json`), `sessions.json`, `access_token.json`, or any other production JSON file in `data/` while the server is running.** All production JSON files in `data/` are edited ONLY with the server stopped. Any fields that the app manages (password hashes, session tokens, paid/archived payrolls, audit chain, exchange-rate snapshots) must not be hand-edited at all.

> **RULES ABOUT SECRETS AND BUSINESS DATA:** the operator enters all real passwords, company names, branches, currencies and all other business values manually. The agent (opencode) must never generate, guess, or insert real passwords or company information — only the placeholders in the template are provided.

## B. FIRST SUPER ADMIN (manual, server stopped)
`data\users.json` must be an array. Minimal entry (schema verified against `server.js` login code):
```json
[
  {
    "id": "usr-admin",
    "username": "YOUR_ADMIN_USERNAME",
    "password": "YOUR_OWN_STRONG_PASSWORD",
    "name": "System Administrator",
    "email": "YOUR_ADMIN_EMAIL",
    "role": "super_admin",
    "assignedCompanyId": "all",
    "assignedBranchId": "all"
  }
]
```
- **username:** any string; login matches `username` OR `email`, case-insensitively.
- **password placeholder → operator-only:** set `YOUR_OWN_STRONG_PASSWORD` yourself. Never accept a password generated by an agent.
- **role = `super_admin` (exact string).** Grants all permissions.
- **assignedCompanyId = `all`** and **assignedBranchId = `all`** (explicitly set; they default to `all` anyway for any user).
- **Password migration (verified):** a plaintext password is accepted by the first login and is auto-upgraded in place to PBKDF2 (pbkdf2$salt$iter$hash, 100k iterations) on the FIRST successful login. Optional pre-hash before first login: `npm run migrate` (backs up `data/users.json` to `data/backups/` first, verifies, idempotent).
- **Only `username` + `password` are truly mandatory for login**; the other fields above are recommended.

## C. PRODUCTION ENVIRONMENT (Windows env vars, same console; no `.env` file is read)
```bat
set NODE_ENV=production
set PORT=5173
set CORS_ALLOWLIST=http://localhost:5173,http://127.0.0.1:5173
node server.js
```
- `NODE_ENV=production` + a non-empty, non-wildcard `CORS_ALLOWLIST` are enforced: the server refuses to start otherwise.
- List **both** `http://localhost:5173` and `http://127.0.0.1:5173` (exact-match validation; `localhost` ≠ `127.0.0.1`). Add LAN/tunnel origins later as needed.
- Tip: save these lines as a copy of `start.bat` (the shipped `.bat` files run dev mode).

## D. FIRST START
- [ ] Run `node server.js` (with the C section env set). Expected banner: production mode, explicit allowlist, data dir `./data`, access-token status.
- [ ] Open `http://localhost:5173`. `GET /api/status` expected (no token set): `200 {"status":"ok","protected":false}`.
- [ ] Log in with the password you set in B (this is the first login — the password is hashed at this moment).

## E. FIRST LOGIN SAFETY CHECK (immediately after login, before entering data)
- [ ] **No demo company `comp-1`** ("الشركة الرئيسية") in Companies. If it appeared (browser may push the bundled demo if `data/companies.json` was missing/empty), delete it now.
- [ ] **No demo employees** (Employees list empty).
- [ ] **No demo payroll** (Payroll empty).
- [ ] **Only the intended super_admin** exists in Users.
- [ ] Settings shows defaults only.
> Verified behavior: the first login can push a demo `comp-1` company into an empty/missing `companies.json`. Prevent it by pre-creating `data/companies.json` with your real company (server stopped) before first login, or by deleting `comp-1` right after login. Employee/payroll/etc. defaults are empty arrays — nothing else is auto-pushed.

## F. COMPANY / BRANCH SETUP (super_admin, via Companies screen)
- **Mandatory company fields:** Company Name (Arabic) `nameAr`, Company Code `code`, Currency (+ symbol, default SAR), and Initial Main Branch Name (`mainBranchName`). Optional: `nameEn`, Commercial Registration, Tax Number, `hourlyLeaveQuota` (default 4).
- **Branch behavior (verified):** creating a company automatically creates the FIRST MAIN BRANCH (`id br-<ts>`, city = الرئيسي, `payDay = 25`). Add more branches with "+ Add Branch": mandatory Branch Name (Arabic), Branch Type (main/sub), City; optional nameEn, Payday. Sub-branches select a parent main branch.
- **No guessed business values:** enter your real names/codes/currencies manually. The agent never supplies company/branch data.
